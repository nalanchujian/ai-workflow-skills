# 工作流版本发布指南

## 要解决的问题

本指南面向 `ai-workflow-skills` 维护者，说明当前 MVP 如何发布技能仓库快照。

为降低使用和维护成本，AIW 自有模板与阶段技能暂时统一使用 `0.0.1`；Superpowers 方法保留上游版本。Git tag 标识用户安装的完整仓库快照。

```text
技能仓库 Git tag：v0.0.1
└─ 工作流模板：standard-web-feature@0.0.1
   └─ 阶段技能：统一为 0.0.1
```

## 当前模板

```yaml
name: standard-web-feature
version: 0.0.1
description: 适用于 TypeScript Web 业务需求的简化开发工作流。
aiwCompatibility: ">=0.0.1 <1.0.0"
artifactContract: aiw.task-output/v1
skills:
  clarify: requirements-clarification@0.0.1
  solution: technical-solution@0.0.1
  plan: implementation-planning@0.0.1
  development: typescript-web-implementation@0.0.1
```

每次修改必须确认模板引用存在且阶段匹配，并通过静态校验。当前 MVP 不要求模板和阶段技能随每次修改递增版本；如需重新设计版本策略，应在 MVP 稳定后单独立项。

## 发布步骤

在仓库根目录执行：

```bash
git status --short
node scripts/validate-skill-package.mjs
git add skills/ profiles/ method-sources/ README.md docs/
git commit -m "feat: update standard web workflow"
git tag -a <new-tag> -m "Release standard web workflow"
git push origin main --tags
```

新 tag 必须指向已审阅、已验证的 commit。不要移动已发布 tag，也不要复用同一 tag 发布不同内容。

## 用户如何采用新快照

发布后，用户显式执行：

```bash
aiw skills update --ref <new-tag>
```

更新不会自动触发。新建任务使用更新后的默认模板；进行中的任务继续使用创建时锁定的 Git revision。

## 协议边界

每个 `SKILL.md` 和 `PROFILE.yaml` 都必须声明：

```yaml
aiwCompatibility: ">=0.0.1 <1.0.0"
artifactContract: aiw.task-output/v1
```

技能正文只描述方法、输入、步骤和输出；不得固化任务目录、产物目录、运行目录、平台产物文件名、Schema 版本、字段白名单或完整 YAML 示例。字段和物理路径由 AIW 运行时生成。

## 对进行中任务的影响

AIW 的本机技能 Registry 按 Git revision 保留同一来源的多个已安装快照。任务创建时锁定模板、技能、方法来源和 Git revision。

- 用户可以在存在进行中任务时更新技能仓库。
- 新任务使用新的默认快照。
- 进行中的旧任务继续按已锁定 revision 解析技能和方法来源。
- 不要手动修改已有任务中的技能版本或 revision。
