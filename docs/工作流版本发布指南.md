# 工作流版本发布指南

## 要解决的问题

本指南面向 `ai-workflow-skills` 的维护者，定义如何升级 `standard-web-feature`、其阶段技能以及整个技能仓库的 Git 发布版本。

用户只选择工作流模板；维护者必须同时管理三层版本：

```text
技能仓库 Git tag：v4.0.0
└─ 工作流模板：standard-web-feature@4.0.0
   └─ 阶段技能：implementation-planning@4.0.0（示例）
```

| 对象 | 记录位置 | 回答的问题 |
|---|---|---|
| 技能仓库 Git tag | Git tag，例如 `v4.0.0` | 用户下载的是哪一个完整技能包快照？ |
| 工作流模板版本 | `profiles/standard-web-feature/PROFILE.yaml` 的 `version` | 任务采用哪一套固定七阶段流程？ |
| 阶段技能版本 | `skills/<name>/SKILL.md` front matter 的 `version` | 某个阶段实际使用哪一版规则？ |

## 何时升级

### 仅发布 Git tag，模板版本不变

以下改动不改变 `standard-web-feature` 的执行行为：

- 修改 README、示例、注释或许可证说明；
- 新增不被 `standard-web-feature` 引用的模板或技能；
- 修改其他模板的规则。

此时创建新的 Git tag，例如 `v4.0.1`，但 `standard-web-feature` 仍保持 `4.0.0`。

### 升级阶段技能与模板版本

以下改动改变当前工作流的实际执行行为，必须升级受影响阶段技能和 `standard-web-feature`：

- 改变某阶段的输入、步骤、必需产物或验证要求；
- 改变工作流七阶段映射；
- 升级或替换引用的方法来源；
- 扩大或收紧实现、验证、安全边界。

例如实施阶段规则变化时：

1. 修改 `skills/typescript-web-implementation/SKILL.md`，将 front matter 的 `version` 从 `2.0.0` 升为 `2.1.0`；
2. 修改 `profiles/standard-web-feature/PROFILE.yaml`：

```yaml
name: standard-web-feature
version: 4.1.0
description: 适用于 TypeScript Web 业务需求的标准七阶段方法。
skills:
  clarify: requirements-clarification@3.0.0
  solution: technical-solution@3.0.0
  plan: implementation-planning@4.0.0
  implement: typescript-web-implementation@2.1.0
  verify: web-verification@2.0.0
  test: acceptance-testing@3.0.0
```

3. 确认模板引用的每一个 `name@version` 都在同一仓库版本中存在且阶段匹配；
4. 完成审阅与验证后提交，并发布新的 Git tag，例如 `v4.1.0`。

建议遵循语义化版本：修正不改变执行语义的错误用 PATCH；新增兼容能力用 MINOR；移除阶段、改变必需产物或引入不兼容执行方式用 MAJOR。例如计划阶段新增 `implementation-context.md`、`work-breakdown.yaml` 等必需产物，或改变计划审批后的实施任务图，均属于 MAJOR。

## 发布步骤

在 `ai-workflow-skills` 仓库根目录执行：

```bash
git status --short
git add skills/ profiles/ method-sources/ README.md docs/
git commit -m "feat: update standard web workflow"
git tag -a v4.1.0 -m "Release standard web workflow 4.1.0"
git push origin main --tags
```

tag 必须指向已审阅、已验证的 commit。不要移动已发布 tag，也不要复用同一个 tag 发布不同内容。

## 用户如何采用新版本

发布后，用户显式执行：

```bash
aiw skills update --ref v4.1.0
```

更新不会自动触发。用户是否采用新版、何时采用新版，应由团队发布策略决定。

更新成功后，`aiw` 会以用户当前默认模板名为锚点，在新技能包中选择同名模板的新版本，并将本机默认 Git tag 与模板引用一并切换。例如 `standard-web-feature@4.0.0` 会切换为新包提供的 `standard-web-feature@4.1.0`。新包没有该模板时，用户本机默认配置保持不变。

## 当前实现限制：升级前检查进行中任务

`aiw` 当前的本机技能 Registry 在更新同一 Git 来源时会替换该来源的已安装技能和模板。已创建任务虽然在业务仓库中锁定了模板版本、Git revision 和哈希，但其运行仍要在本机 Registry 找到对应技能。

因此，在“多版本并存 Registry”实现前：

- 有正在执行的任务时，不要运行 `aiw skills update`；
- 先完成、归档或在团队治理下处理旧任务；
- 仅为新任务升级时，确保本机没有需要继续运行的旧版本任务。

这是当前运行时限制，不应通过修改任务文件或伪造版本号绕过。后续 `aiw` 应实现按来源 revision 保留多个已安装版本，使新旧任务可以并行执行。
